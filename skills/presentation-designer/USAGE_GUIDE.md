# Using Presentation Designer with AI Agents

This guide shows you how to use the presentation design documents generated by this tool to create actual presentations with AI assistance.

## Basic Workflow

```bash
# Step 1: Design your presentation
node designer.js --output my-presentation.yaml

# Step 2: Review and refine the design
vim my-presentation.yaml  # or your favorite editor

# Step 3: Generate the presentation with an AI agent
pi "Create a Typst presentation using Polylux based on my-presentation.yaml"
```

## What AI Agents Can Do With Your Design

The design document contains everything an AI agent needs to generate a structured presentation:

### From Metadata
- Set document title, author, date
- Configure presentation type and duration

### From Purpose
- Create an opening that hooks the audience
- Ensure slides align with stated objectives
- Include elements that support success criteria

### From Audience
- Adjust technical complexity appropriately
- Choose relevant examples and references
- Set appropriate tone and pacing

### From Key Messages
- Ensure messages are prominently featured
- Structure content to support these messages
- Create summaries that reinforce them

### From Structure
- Create sections with title slides
- Generate the right number of slides per section
- Allocate content appropriately
- Plan timing and flow

### From Visual Style
- Set theme colors
- Configure fonts
- Apply consistent layouts
- Add visual elements

### From Content Guidelines
- Set appropriate tone
- Choose complexity level
- Follow dos and don'ts
- Maintain consistency

## Example Prompts for AI Agents

### Basic Generation

```
Using the design document in conference-talk.yaml, create a complete Typst 
presentation using the Polylux package. Follow the structure exactly and 
implement the visual style specified.
```

### With Specific Requirements

```
Based on workshop.yaml, create a Typst presentation that:
1. Uses the Touying framework instead of Polylux
2. Includes speaker notes for each slide
3. Adds placeholder images where diagrams are mentioned
4. Uses the JetBrains Mono font for code examples
```

### Iterative Refinement

```
I have a design document (pitch.yaml) and a draft presentation (pitch.typ).
Please review the presentation against the design and:
- Ensure all sections from the design are present
- Verify the visual style matches
- Check that key messages are emphasized
- Suggest improvements
```

### Section-by-Section Generation

```
Using conference-talk.yaml as reference, generate just the "Key Patterns" 
section (slides 4-10). Make sure to:
- Follow the content list exactly
- Use the code_font specified in visual_style
- Keep the technical tone from content_guidelines
```

## Tips for Best Results

### Be Specific in Your Design

The more detailed your design document, the better the AI output:

**Vague:**
```yaml
content:
  - "Talk about the solution"
```

**Specific:**
```yaml
content:
  - "Show architecture diagram with 3 components"
  - "Code example: implementing circuit breaker"
  - "Comparison table: before vs after"
```

### Include Examples and References

If your presentation should follow a specific style:

```yaml
technical_notes:
  style_references:
    - "Similar to Apple keynote style - minimal text, big visuals"
    - "See examples/conference-talk.yaml for layout ideas"
```

### Specify Visual Elements

Instead of:
```yaml
visual_elements:
  - "Diagrams"
```

Use:
```yaml
visual_elements:
  - "Architecture diagram showing microservices with arrows"
  - "Sequence diagram for authentication flow"
  - "Bar chart comparing performance metrics"
```

### Plan for Placeholders

Your design should indicate where you'll need to add custom content:

```yaml
content:
  - "[PLACEHOLDER: Team photo with 4 founders]"
  - "Live demo of dashboard (screenshot as backup)"
  - "[TODO: Add latest customer count metric]"
```

## Advanced Usage

### Template-Based Generation

Create a reusable template design:

```bash
# Create template
node designer.js --output templates/tech-talk-template.yaml

# Use template as starting point for new presentations
cp templates/tech-talk-template.yaml my-new-talk.yaml
# Edit my-new-talk.yaml with new content
# Generate presentation
```

### Combining Multiple Designs

For complex presentations, you might design sections separately:

```yaml
# main-presentation.yaml
structure:
  sections:
    - name: "Introduction"
      design_file: "sections/intro.yaml"
    - name: "Technical Deep Dive"  
      design_file: "sections/technical.yaml"
    - name: "Conclusion"
      design_file: "sections/conclusion.yaml"
```

### Version Control

Track changes to your presentation design:

```bash
git init
git add presentation-design.yaml
git commit -m "Initial presentation design"

# After feedback
vim presentation-design.yaml
git commit -am "Simplified technical section based on feedback"
```

## Troubleshooting

### AI Agent Doesn't Follow Design

If the generated presentation doesn't match your design:

1. **Be more specific** - Add more detail to vague sections
2. **Reference the design explicitly** - "According to the design document..."
3. **Break it down** - Ask for one section at a time
4. **Provide examples** - Link to similar presentations or styles

### Design is Too Detailed

If your design is overwhelming the AI:

1. Start with a simpler design
2. Generate basic structure first
3. Refine section by section
4. Keep iterations small

### Style Not Applied Correctly

For visual style issues:

1. Provide Typst/Polylux theme code examples
2. Reference existing themes ("Use metropolis theme as base")
3. Be specific about colors (use hex codes, not names)
4. Show before/after examples

## Integration Examples

### With Pi Coding Agent

```bash
# Design
node designer.js --output rust-intro.yaml

# Generate
pi "Using rust-intro.yaml, create a Typst presentation with:
- Polylux for slides
- Catppuccin color scheme from visual_style
- Code highlighting for Rust
- Speaker notes from content items"

# Refine
pi "Update slides 5-8 to include more code examples as specified 
in the design's visual_elements section"
```

### With Other AI Tools

The YAML/JSON format is universal - use with any AI assistant:

**ChatGPT/Claude:**
1. Upload the design YAML
2. Ask: "Create a Typst presentation based on this design"

**GitHub Copilot:**
1. Open design.yaml alongside new .typ file
2. Add comment: `// Generate presentation from design.yaml`
3. Let Copilot generate structure

## Best Practices

1. **Design First, Build Later** - Resist urge to start coding slides immediately
2. **Get Feedback on Design** - Easier to change YAML than regenerate slides
3. **Keep Design Updated** - As presentation evolves, update the design doc
4. **Version Both** - Track both design and generated presentation
5. **Reuse Patterns** - Build library of design templates for common scenarios
