## PART I: Requirements

### Problem Statement

The three pipelines (ingest, search, delete) are implemented and tested in isolation. This feature wires them together behind an MCP server that speaks the Model Context Protocol over stdio, making the RAG system usable as a Claude tool server.

Claude Desktop, Claude Code, and any other MCP client connect to the server by launching the binary and communicating over stdin/stdout using the MCP JSON-RPC protocol. The server must register three tools (`ingest`, `search`, `delete_source`), expose them with well-typed JSON schemas, route calls to the appropriate pipeline, translate pipeline results and errors into `CallToolResult` values, and remain alive until the client closes the connection.

A secondary concern is stdio safety: `main.rs` currently emits `println!` calls that would corrupt the MCP JSON-RPC stream. All logging must be routed to stderr before the server starts accepting connections.

### Requirements

- **R1** — Three new Cargo dependencies: `rmcp` (features: `server`, `macros`, `transport-io`, `schemars`), `schemars` (version `0.8`), and `tracing-subscriber` (features: `env-filter`). `rmcp` re-exports `schemars` from its own crate; the local `schemars` dep is for our `#[derive(JsonSchema)]` usage on request structs. No other new dependencies are needed.

- **R2** — `McpServer` struct (`src/mcp/mod.rs`): holds `tool_router: ToolRouter<McpServer>`, `ingest: IngestPipeline`, `search: SearchPipeline`, and `delete: DeletePipeline`. Derives `Clone` (all fields are `Clone`). The `tool_router` field is populated by `Self::tool_router()`, generated by the `#[tool_router]` macro.

- **R3** — Three request parameter structs, derived with `serde::Deserialize` and `schemars::JsonSchema`:
  - `IngestParams { content: String, filename: String, content_type: String, metadata: Option<serde_json::Value> }` — `metadata` defaults to `serde_json::Value::Object(Default::default())` when absent.
  - `SearchParams { query: String, k: Option<i64> }` — `k` defaults to `5` when absent.
  - `DeleteSourceParams { source_id: String }` — accepts a UUID as a plain string; parsed to `Uuid` at call time.

- **R4** — Three tool methods on `McpServer`, each marked `#[tool(description = "...")]` inside a `#[tool_router]` impl block, each returning `Result<CallToolResult, McpError>`. Methods are `async` where they call pipelines. Tool names default to the method name (snake_case).

- **R5** — `ingest` tool: validates `source_id` parsing is not needed (no UUID input). Calls `self.ingest.ingest(...)`. On success, serializes the `Source` struct to a JSON string and returns `CallToolResult::success(vec![Content::text(json_string)])`. On error, delegates to `app_error_to_mcp_error`.

- **R6** — `search` tool: resolves `k.unwrap_or(5)`. Calls `self.search.search(query, k)`. On success, serializes `Vec<SearchResult>` to a JSON string and returns `CallToolResult::success(vec![Content::text(json_string)])`. An empty result set is returned as an empty JSON array (not an error). On error, delegates to `app_error_to_mcp_error`.

- **R7** — `delete_source` tool: parses `source_id: String` → `Uuid` using `Uuid::parse_str`. If parsing fails, returns a tool-level error immediately (not a server error). Calls `self.delete.delete(uuid)`. On success, returns `CallToolResult::success(vec![Content::text("source deleted")])`. On error, delegates to `app_error_to_mcp_error`.

- **R8** — `ServerHandler` for `McpServer` via the `#[tool_handler]` macro on an `impl ServerHandler for McpServer` block. `get_info()` returns a `ServerInfo` with `ServerCapabilities::builder().enable_tools().build()` and the server name `"rag-mcp"`.

- **R9** — Error translation helper `app_error_to_mcp_error(e: AppError) -> McpError`:
  - `AppError::Validation(msg)` → `McpError::invalid_params(msg, None)` — caller error, no logging.
  - `AppError::NotFound(msg)` → `McpError::invalid_params(msg, None)` — caller error, no logging.
  - All other variants → log `tracing::error!(error = %e, "tool call internal error")` and return `McpError::internal_error("internal error", None)` — never expose internal details to the caller.

- **R10** — `serve` command wiring in `main.rs`: replace the current stub with:
  1. Initialize `tracing_subscriber::fmt()` with `EnvFilter`, `with_writer(std::io::stderr)`, and `with_ansi(false)` — routes all logs to stderr.
  2. Replace `println!` calls with `tracing::info!`.
  3. Construct `EmbeddingService::new(&config.embedding_model)?`.
  4. Construct `S3Storage::new(&config).await?`.
  5. Construct `ChunkConfig { chunk_size: config.chunk_size, overlap: config.chunk_overlap }`.
  6. Construct the three pipelines.
  7. Construct `McpServer::new(ingest_pipeline, search_pipeline, delete_pipeline)`.
  8. Call `.serve(stdio()).await?` and then `.waiting().await?`.

- **R11** — `McpServer::new(ingest: IngestPipeline, search: SearchPipeline, delete: DeletePipeline) -> Self`: simple constructor. Populates `tool_router: Self::tool_router()`.

- **R12** — `src/pipelines/mod.rs`: add `pub mod delete;` (if not already present from F9). The final state must export all three pipeline modules.

- **R13** — No changes to `src/error.rs`, `src/config.rs`, or any pipeline files. All error variants (`Validation`, `NotFound`, `Internal`) already exist. No new pipeline methods are needed.

### Success Criteria

- [ ] `cargo build` compiles with zero errors and zero warnings after adding the three dependencies
- [ ] `McpServer` struct derives `Clone` without additional bounds
- [ ] `ingest` tool: calling with valid content returns a JSON-serialized `Source`; calling with empty content returns a tool-level error (not a panic)
- [ ] `search` tool: calling with a valid query and no `k` returns up to 5 results; calling with an empty query returns a tool-level error; k is clamped by the pipeline's own validation
- [ ] `delete_source` tool: calling with a malformed UUID string returns a tool-level error; calling with a nonexistent valid UUID returns a tool-level error (NotFound); calling with a valid ingested source UUID returns `"source deleted"`
- [ ] No `println!` calls remain in `main.rs`; all log output goes to stderr; MCP JSON-RPC framing on stdout is uncontaminated
- [ ] `cargo run -- serve` (with valid env vars) starts the server, prints nothing to stdout before the MCP handshake, and responds correctly to the MCP `initialize` request
- [ ] Claude Code can connect to the binary and discover the three tools via the MCP tool listing

### Out of Scope

The following are explicitly deferred and must not be implemented in this feature:

- **`list_sources` tool** — deferred per epic scope decision.
- **HTTP/SSE MCP transport** — stdio only in v1; streamable-HTTP transport is a follow-up.
- **Streaming tool results** — all tool responses are returned as a single `CallToolResult`.
- **Authentication / authorization** — no caller identity checks.
- **Per-source filtering in search** — the `search` tool accepts only `query` and `k`; source-scoped search is deferred.
- **Tool input validation beyond what the pipelines already enforce** — `McpServer` does not re-validate chunk sizes, content type strings, etc.
- **Structured JSON content types in `CallToolResult`** — all results are returned as `Content::text` (plain JSON string); MCP structured content is a follow-up.
- **MCP `resources` or `prompts` capabilities** — only `tools` is enabled.

### 3.3 Request Parameter Structs

```rust
// src/mcp/mod.rs

use rmcp::schemars;
use serde::Deserialize;

#[derive(Debug, Deserialize, schemars::JsonSchema)]
pub struct IngestParams {
    /// The full text content of the document to ingest.
    pub content: String,
    /// Human-readable filename (e.g. "design.md").
    pub filename: String,
    /// MIME content type (e.g. "text/plain" or "text/markdown").
    pub content_type: String,
    /// Arbitrary JSON metadata to attach to the source record.
    pub metadata: Option<serde_json::Value>,
}

#[derive(Debug, Deserialize, schemars::JsonSchema)]
pub struct SearchParams {
    /// Natural language query string.
    pub query: String,
    /// Number of results to return (1–100). Defaults to 5.
    pub k: Option<i64>,
}

#[derive(Debug, Deserialize, schemars::JsonSchema)]
pub struct DeleteSourceParams {
    /// UUID of the source to delete (as returned by the ingest tool).
    pub source_id: String,
}
```

All three structs derive `schemars::JsonSchema`. The `rmcp` macro infrastructure reads the generated schema at compile time to populate the MCP tool manifest that clients use for type-checked calls.

### 3.4 `McpServer` Struct

```rust
// src/mcp/mod.rs

use rmcp::handler::server::router::tool::ToolRouter;

use crate::pipelines::{delete::DeletePipeline, ingest::IngestPipeline, search::SearchPipeline};

#[derive(Clone)]
pub struct McpServer {
    tool_router: ToolRouter<McpServer>,
    ingest:      IngestPipeline,
    search:      SearchPipeline,
    delete:      DeletePipeline,
}

impl McpServer {
    pub fn new(
        ingest: IngestPipeline,
        search: SearchPipeline,
        delete: DeletePipeline,
    ) -> Self {
        Self {
            tool_router: Self::tool_router(),
            ingest,
            search,
            delete,
        }
    }
}
```

`ToolRouter<McpServer>` is generated by the `#[tool_router]` macro and is `Clone`. All three pipeline types are `Clone` (each wraps its dependencies in `Arc`). Therefore `McpServer` derives `Clone` without additional bounds.

### 3.5 Tool Implementations

```rust
// src/mcp/mod.rs

use rmcp::{
    ErrorData as McpError,
    handler::server::wrapper::Parameters,
    model::{CallToolResult, Content},
    tool, tool_handler, tool_router,
    ServerHandler,
    model::{ServerCapabilities, ServerInfo},
};
use uuid::Uuid;

use crate::error::AppError;

#[tool_router]
impl McpServer {
    #[tool(description = "Ingest a document into the knowledge base. Uploads the original to S3, chunks the text, embeds the chunks, and persists everything to PostgreSQL. Returns a JSON object with the source record (id, filename, content_type, metadata, created_at).")]
    async fn ingest(
        &self,
        Parameters(params): Parameters<IngestParams>,
    ) -> Result<CallToolResult, McpError> {
        let metadata = params.metadata.unwrap_or_else(|| serde_json::Value::Object(Default::default()));
        let source = self
            .ingest
            .ingest(&params.content, &params.filename, &params.content_type, metadata)
            .await
            .map_err(app_error_to_mcp_error)?;
        let json = serde_json::to_string(&source)
            .map_err(|e| McpError::internal_error(format!("serialization error: {e}"), None))?;
        Ok(CallToolResult::success(vec![Content::text(json)]))
    }

    #[tool(description = "Search the knowledge base with a natural language query. Returns a JSON array of the top-k most semantically relevant chunks, each with content, source_filename, chunk_index, similarity score, and source_metadata. k defaults to 5 (range: 1–100).")]
    async fn search(
        &self,
        Parameters(params): Parameters<SearchParams>,
    ) -> Result<CallToolResult, McpError> {
        let k = params.k.unwrap_or(5);
        let results = self
            .search
            .search(&params.query, k)
            .await
            .map_err(app_error_to_mcp_error)?;
        let json = serde_json::to_string(&results)
            .map_err(|e| McpError::internal_error(format!("serialization error: {e}"), None))?;
        Ok(CallToolResult::success(vec![Content::text(json)]))
    }

    #[tool(description = "Delete a source document and all its associated chunks from the knowledge base. Removes the original from S3 and all chunk/vector records from PostgreSQL. The source_id is the UUID returned by the ingest tool.")]
    async fn delete_source(
        &self,
        Parameters(params): Parameters<DeleteSourceParams>,
    ) -> Result<CallToolResult, McpError> {
        let uuid = Uuid::parse_str(&params.source_id).map_err(|_| {
            McpError::invalid_params(
                format!("source_id is not a valid UUID: '{}'", params.source_id),
                None,
            )
        })?;
        self.delete
            .delete(uuid)
            .await
            .map_err(app_error_to_mcp_error)?;
        Ok(CallToolResult::success(vec![Content::text("source deleted")]))
    }
}
```

The method name `delete_source` matches the MCP tool name exposed to clients. The `ingest` and `search` method names also match their tool names directly. No explicit `name = "..."` attribute is needed on `#[tool]` unless the method name must differ from the tool name.

### 3.7 Error Translation Helper

```rust
// src/mcp/mod.rs

fn app_error_to_mcp_error(e: AppError) -> McpError {
    match e {
        AppError::Validation(msg) => {
            McpError::invalid_params(msg, None)
        }
        AppError::NotFound(msg) => {
            McpError::invalid_params(msg, None)
        }
        other => {
            tracing::error!(error = %other, "tool call internal error");
            McpError::internal_error("internal error", None)
        }
    }
}
```

`Validation` and `NotFound` errors are caller errors — they are safe to surface verbatim. All other error variants (`Database`, `Storage`, `Embedding`, `Internal`, `Io`, etc.) are internal errors — they are logged at `error` level and replaced with a generic message that does not leak internal state (connection strings, S3 bucket names, stack traces) to the MCP client.

### 3.8 Rewritten `main.rs`

```rust
// src/main.rs

mod mcp;

use clap::{Parser, Subcommand};
use rag_mcp::chunking::ChunkConfig;
use rag_mcp::config::Config;
use rag_mcp::db;
use rag_mcp::embedding::EmbeddingService;
use rag_mcp::pipelines::delete::DeletePipeline;
use rag_mcp::pipelines::ingest::IngestPipeline;
use rag_mcp::pipelines::search::SearchPipeline;
use rag_mcp::storage::S3Storage;
use rmcp::{ServiceExt, transport::stdio};
use tracing_subscriber::EnvFilter;

use crate::mcp::McpServer;

#[derive(Parser)]
#[command(
    name = "rag-mcp",
    version,
    about = "RAG MCP Server — semantic search over a document knowledge base"
)]
struct Cli {
    #[command(subcommand)]
    command: Commands,
}

#[derive(Subcommand)]
enum Commands {
    /// Start the MCP server (stdio transport)
    Serve(Config),
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    match dotenvy::dotenv() {
        Ok(_) => {}
        Err(dotenvy::Error::Io(e)) if e.kind() == std::io::ErrorKind::NotFound => {}
        Err(e) => eprintln!("Warning: failed to load .env file: {e}"),
    }

    let cli = Cli::parse();

    match cli.command {
        Commands::Serve(config) => {
            // Route all tracing output to stderr — stdout is reserved for MCP JSON-RPC.
            tracing_subscriber::fmt()
                .with_env_filter(
                    EnvFilter::try_from_default_env()
                        .unwrap_or_else(|_| EnvFilter::new("info")),
                )
                .with_writer(std::io::stderr)
                .with_ansi(false)
                .init();

            tracing::info!("RAG MCP server starting");

            let pool = db::connect(&config.database_url, config.db_max_connections).await?;
            tracing::info!("database connected and migrations applied");

            let storage = S3Storage::new(&config).await?;
            tracing::info!("S3 storage initialised");

            let embedding = EmbeddingService::new(&config.embedding_model)?;
            tracing::info!(model = %config.embedding_model, "embedding service loaded");

            let chunk_config = ChunkConfig {
                chunk_size: config.chunk_size,
                overlap:    config.chunk_overlap,
            };

            let ingest_pipeline = IngestPipeline::new(
                pool.clone(),
                storage.clone(),
                chunk_config,
                embedding.clone(),
            );
            let search_pipeline = SearchPipeline::new(pool.clone(), embedding.clone());
            let delete_pipeline = DeletePipeline::new(pool.clone(), storage.clone());

            let server = McpServer::new(ingest_pipeline, search_pipeline, delete_pipeline);

            tracing::info!("MCP server ready; listening on stdio");

            let service = server
                .serve(stdio())
                .await
                .inspect_err(|e| tracing::error!(error = ?e, "MCP serve error"))?;

            service.waiting().await?;

            tracing::info!("MCP server shut down cleanly");
            Ok(())
        }
    }
}
```

Key points:
- `tracing_subscriber::fmt()` is initialized before any `tracing::info!` calls and before `stdio()` is opened. This ensures the very first log line goes to stderr, not stdout.
- `EnvFilter::try_from_default_env()` falls back to `"info"` if `RUST_LOG` is not set.
- `with_ansi(false)` avoids ANSI escape codes in log output, which can confuse log aggregators.
- All three `println!` calls from the old stub are replaced with `tracing::info!`.
- `stdio()` from `rmcp::transport` creates a transport over `tokio::io::stdin()` / `tokio::io::stdout()`.
- `.serve(stdio()).await?` performs the MCP handshake and registers the tool manifest.
- `.waiting().await?` blocks until the client closes the connection (EOF on stdin).

### 3.12 MCP Tool Manifest (What Clients See)

After the `initialize` handshake, clients that call `tools/list` will receive:

| Tool name | Description summary | Required inputs | Optional inputs |
|-----------|---------------------|-----------------|-----------------|
| `ingest` | Ingest a document into the knowledge base | `content`, `filename`, `content_type` | `metadata` |
| `search` | Search with a natural language query | `query` | `k` (default 5) |
| `delete_source` | Delete a source and all its chunks | `source_id` | — |

JSON schemas are auto-generated from `IngestParams`, `SearchParams`, and `DeleteSourceParams` by `schemars`. Doc comments on struct fields and the tool description strings are surfaced to the client in the manifest.

## PART IV: Open Questions

| # | Question | Default / Fallback |
|---|----------|--------------------|
| Q1 | Should `ingest` return `(source_id, chunk_count)` rather than the full `Source` JSON, to reduce response size? | Return full `Source` JSON for v1 — the MCP tool layer can always omit fields, but adding them back later requires a protocol change. Chunk count can be computed by the caller if needed. |
| Q2 | Should `search` return structured JSON content (MCP `Content::json(...)`) instead of a JSON string in `Content::text(...)`? | `Content::text` (JSON string) for v1. Structured content types have inconsistent support across MCP clients; plain JSON text works everywhere. Revisit once client support matures. |
| Q3 | Should the server log each tool call with method name, latency, and outcome for observability? | Not in v1. A middleware-level tracing layer (wrapping all tool calls) would be the right abstraction — defer until there is a clear operational need. Basic `tracing::info!` at startup is sufficient for v1. |
| Q4 | Should `delete_source` accept a source UUID via a strongly typed `uuid::Uuid` parameter rather than a `String`? | `String` for v1. `schemars` does not produce a `format: "uuid"` schema for `uuid::Uuid` without additional configuration, and MCP clients benefit from the explicit string representation. Parse to `Uuid` at call time (R7). |
| Q5 | Should the server handle `SIGTERM` / `SIGINT` for graceful shutdown? | Not in v1. `service.waiting().await` blocks until stdin reaches EOF, which is how MCP clients signal shutdown. Signal handling (for process-managed deployments) is a follow-up. |
| Q6 | Should `rmcp` use the `transport-io` feature or the `transport-sse-server` feature? | `transport-io` only for v1 — stdio is the correct transport for Claude tool servers. SSE/HTTP transport is explicitly out of scope per the epic. |
